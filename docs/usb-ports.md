# USB-C 포트 가이드 (왼쪽 vs 오른쪽)

YD-ESP32-S3 에는 USB-C 포트가 **2개** 있어 처음엔 어느 쪽에 꽂아야 할지 헷갈립니다.
결론부터 말하면 — **양쪽 모두 펌웨어 다운로드와 시리얼 로그가 둘 다 됩니다.** 차이는
"무엇만 되냐"가 아니라 **"얼마나 안정적이냐 + 특수 기능"** 입니다.

> **방향 기준:** 부품면(앞면)이 자신을 향하게 하고, 두 USB-C 커넥터가 **아래쪽**
> 가장자리에 오도록 보드를 잡으세요. 좌/우는 보드 방향에 따라 뒤집히므로, 커넥터 옆의
> **실크스크린 라벨 `USB` / `COM`** 을 최종 기준으로 삼으세요.

---

## 비교표

| 항목 | 왼쪽 (`USB`, 네이티브) | 오른쪽 (`COM`, CH343) |
|------|------------------------|------------------------|
| 연결 대상 | ESP32-S3 **네이티브 USB** (USB-Serial-JTAG), GPIO19(D−)/GPIO20(D+) | **CH343P** USB-to-UART 브리지 |
| 펌웨어 다운로드 | ✅ 됨 | ✅ 됨 |
| 시리얼 로그 | ✅ 됨 | ✅ 됨 |
| 자동 리셋(버튼 없이 플래시) | USB-Serial-JTAG 경유 | ✅ DTR/RTS 회로, **가장 안정적** |
| JTAG 디버깅 | ✅ **이쪽만 가능** | ❌ |
| 앱이 GPIO19/20 사용 시 | 연결 끊길 수 있음 | 영향 없음 |
| Linux 장치 | `/dev/ttyACM*` | `/dev/ttyACM*` (CH343) |
| VID:PID | `303a:1001` (다운로드 모드 `303a:4001`) | `1A86:55D3` |

---

## 언제 무엇을 쓰나

### 왼쪽 포트 (네이티브 USB — "USB")

- ESP32-S3 **JTAG 디버깅** (JTAG 은 이 포트로만 가능)
- **USB 디바이스 기능** 개발 (HID, MSC, CDC, TinyUSB 등)
- 펌웨어가 GPIO19/20 을 재설정하지 않는다면 빠른 플래시/모니터링
- ⚠️ 주의: 애플리케이션이 USB 핀(GPIO19/20)이나 USB 주변장치를 점유하면 이 포트의
  시리얼 연결이 끊길 수 있습니다. 그럴 땐 **수동 다운로드 모드**(BOOT 누른 채 RST 탭 후
  BOOT 뗌)로 플래시해야 할 수 있습니다.

### 오른쪽 포트 (USB-to-UART — "COM")

- **펌웨어 플래시와 시리얼 로그 확인에 가장 안정적**: CH343 이 자동 리셋(DTR/RTS)
  회로를 구동하므로, 버튼을 누르지 않아도 esptool 이 부트로더에 진입합니다.
- 애플리케이션이 네이티브 USB 핀(GPIO19/20)을 다른 용도로 쓰더라도 시리얼 로깅이 계속
  동작합니다.
- **기본 개발/플래시 포트로 권장.** (단, JTAG 불가.)

---

## 결론 — 이렇게 기억하세요

- **평소엔 오른쪽(`COM`) 하나만** 쓰면 됩니다. 플래시도 로그도 다 되고 제일 안정적.
- **왼쪽(`USB`)** 은 JTAG 디버깅이나 USB 디바이스 기능 개발이 필요할 때만.

> Linux 에서 어느 포트인지 확인: `lsusb` 또는 진단 도구 출력의 VID:PID 로 구분.
> `1A86:55D3` → 오른쪽(COM/CH343), `303a:xxxx` → 왼쪽(네이티브 USB).
